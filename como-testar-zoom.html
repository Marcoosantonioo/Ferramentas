Como testar o zoom de uma página

Um guia prático para verificar se textos, conteúdos e funcionalidades continuam acessíveis quando a página é ampliada.

Antes de começar

Você vai comparar a página no tamanho normal com a mesma página ampliada. O objetivo é identificar textos cortados, elementos sobrepostos e funcionalidades que deixam de funcionar.

Por que realizar este teste?

Algumas pessoas precisam aumentar o tamanho do conteúdo para conseguir ler e utilizar uma página. Quando ela não se adapta corretamente à ampliação, informações e controles podem ficar escondidos, cortados ou difíceis de usar.

Quem se beneficia?

  • Pessoas com baixa visão: podem precisar ampliar textos e outros elementos para percebê-los.
  • Pessoas que têm dificuldade para ler textos pequenos: podem escolher um tamanho mais confortável para a leitura.
  • Pessoas que utilizam telas menores ou janelas estreitas: também se beneficiam quando o conteúdo se reorganiza de acordo com o espaço disponível.

Uma página que funciona bem ampliada permite que essas pessoas acessem informações e utilizem as funcionalidades com mais autonomia.

Conheça os testes

Use as setas do teclado para a esquerda e para a direita para percorrer os cartões, ou utilize os botões de navegação quando disponíveis.

  • Redimensionamento de texto

    Zoom de 200%

    WCAG 1.4.4 — Redimensionamento de texto
    Nível AA

    Verifique se o texto pode ser ampliado e se o conteúdo e as funcionalidades continuam disponíveis.

    Esse teste ajuda a identificar situações em que textos ampliados ficam cortados, se sobrepõem ou deixam de aparecer.

    Confira também se a pessoa ainda consegue acessar instruções, preencher campos e usar botões e links. O conteúdo pode mudar de posição, desde que continue disponível e utilizável.

  • Reorganização do conteúdo

    Zoom de 400%

    WCAG 1.4.10 — Refluxo
    Nível AA

    Verifique se o conteúdo se reorganiza para caber em uma área estreita, sem exigir rolagem em duas direções, salvo exceções.

    Ao ampliar a página, colunas podem passar a aparecer uma abaixo da outra, linhas de texto podem quebrar e menus podem mudar de formato.

    Para conteúdo normalmente lido com rolagem vertical, a referência do teste é uma área útil de 320 pixels CSS de largura. Algumas partes, como determinadas tabelas e mapas, podem precisar de rolagem lateral.

    Cartão 2 de 3 +

  • Antes de testar

    Zoom, escala e resolução: qual é a diferença?

    Zoom do navegador: aumenta ou diminui o conteúdo da página. É essa configuração que você ajustará para 200% e 400% durante o teste.

    Escala do sistema: altera o tamanho de textos e elementos em todo o computador. No Windows, por exemplo, ela pode estar configurada em 100% ou 150%.

    Resolução da tela: informa a quantidade de pixels exibidos no monitor, como 1920 × 1080 ou 1920 × 1200.

    Você não precisa de uma resolução específica para testar. Porém, a resolução, a escala do sistema e o tamanho da janela influenciam o espaço disponível no navegador. Por isso, registre essas configurações e siga as orientações de largura no teste de 400%.

    Cartão 3 de 3 +

1. Prepare o teste

  1. Abra no navegador a página que será avaliada. Se necessário, entre na conta e acesse a área desejada.
  2. Coloque o zoom do navegador em 100%. No menu do navegador, procure a opção Zoom. Você também pode usar Ctrl + 0 no Windows ou ⌘ + 0 no Mac.
  3. Observe a página inteira e identifique textos, imagens, menus, botões, formulários, mensagens e outros conteúdos importantes. Abra menus e seções expansíveis para conhecer seu conteúdo.
  4. Anote o navegador, a resolução da tela, a escala do sistema e o tamanho da janela. Essas informações ajudam a reproduzir o teste.

Se a página tiver formulários, diálogos ou etapas diferentes, teste também esses estados. Use dados de teste e evite realizar operações reais, como pagamentos, sem autorização.

2. Teste com zoom de 200%

Critério relacionado: WCAG 2.2, 1.4.4 — Redimensionamento de texto, nível AA.

Como fazer

  1. Com a página aberta, aumente o zoom pelo menu do navegador até 200%. Você também pode usar Ctrl + + no Windows ou ⌘ + + no Mac. Confira o percentual no menu.
  2. Verifique se o texto ficou ampliado em relação à visualização de 100%.
  3. Percorra a página de cima a baixo. Se houver barra de rolagem horizontal, use-a para verificar se existe conteúdo fora da área visível e se ele continua acessível.
  4. Compare o resultado com o que você observou em 100%. Abra menus, seções expansíveis e diálogos para verificar conteúdos que possam ter mudado de lugar.
  5. Teste as funcionalidades: clique nos botões e links, preencha campos e confira se mensagens e instruções continuam disponíveis.
O que observar

Se a página for responsiva: ela pode mudar de formato, por exemplo, transformar colunas em uma lista ou colocar o menu dentro de um botão. Isso não é, por si só, um problema: confira se as informações e funções continuam acessíveis.

Se a página não mudar de formato: verifique se é possível alcançar todo o conteúdo e se nada ficou cortado ou inutilizável.

E se aparecer uma barra de rolagem horizontal?

Para o critério 1.4.4 — Redimensionamento de texto, a presença de uma barra horizontal, por si só, não significa automaticamente uma falha. O conteúdo e as funcionalidades devem continuar disponíveis.

Porém, conseguir alcançar o conteúdo usando a barra não significa que a página também passou no teste de refluxo, critério 1.4.10. Esse critério deve ser avaliado separadamente, nas condições de largura descritas no teste de 400%.

3. Teste com zoom de 400%

Critério relacionado: WCAG 2.2, 1.4.10 — Refluxo, nível AA.

Refluxo é a reorganização do conteúdo para caber no espaço disponível. Por exemplo, duas colunas podem virar uma só, e linhas de texto podem quebrar automaticamente.

Como preparar a largura

Para páginas normalmente lidas com rolagem vertical, o critério usa como referência uma área útil de 320 pixels CSS de largura. A área útil é a região do navegador onde a página aparece — não é a resolução física do monitor.

  1. Volte o zoom para 100%.
  2. Ajuste a janela para que a área útil da página tenha aproximadamente 1280 pixels CSS de largura. Essa é uma forma prática de chegar a 320 pixels CSS após aplicar zoom de 400%.
  3. Aumente o zoom para 400% e confirme, se possível, que a área útil resultante está próxima de 320 pixels CSS.
Como conferir a largura da área útil
  1. Abra as ferramentas de desenvolvedor do navegador. Em muitos navegadores, isso pode ser feito com F12.
  2. Abra a aba Console, digite window.innerWidth e pressione Enter. O número apresentado indica a largura interna da janela em pixels CSS.
  3. Se as ferramentas estiverem abertas ao lado da página, elas podem reduzir a largura medida. Prefira posicioná-las na parte inferior ou em uma janela separada. Confira novamente após alterar o posicionamento.

O valor pode variar um pouco conforme o navegador e as barras de rolagem. Registre a largura efetivamente testada.

Outra forma de verificar o refluxo é ajustar a área útil diretamente para 320 pixels CSS. Isso ajuda a avaliar a largura, mas não substitui a observação do comportamento da página com o zoom aplicado.

Como verificar

  1. Percorra a página de cima a baixo e compare seu conteúdo com a visualização em 100%.
  2. Observe se textos, menus, formulários e controles se reorganizam dentro da largura disponível.
  3. Verifique se é necessário rolar para a esquerda e para a direita para ler textos comuns ou utilizar controles.
  4. Se aparecer uma barra horizontal, identifique qual conteúdo está causando a rolagem e verifique se ele se enquadra em uma das exceções explicadas abaixo.
  5. Abra menus, seções expansíveis e diálogos. Teste os controles e confirme que as informações continuam disponíveis.
O que observar

Quando a rolagem lateral não é esperada?

Em uma página normalmente lida de cima para baixo, com área útil de 320 pixels CSS de largura, textos e controles comuns devem se reorganizar para caber no espaço disponível.

Por exemplo, uma pessoa não deve precisar rolar para a direita e voltar para a esquerda a cada linha de um parágrafo. O mesmo cuidado se aplica a conteúdos como títulos, instruções, campos e botões que possam se reorganizar.

Se esses conteúdos exigirem rolagem nas duas direções para serem lidos ou utilizados, isso pode indicar uma falha do critério 1.4.10 — Refluxo.

Quando a rolagem lateral é permitida?

O critério de refluxo permite uma exceção para partes do conteúdo que precisam de uma organização em duas dimensões para fazer sentido ou funcionar.

Alguns exemplos são:

  • Tabelas de dados: quando é necessário manter a relação entre linhas e colunas para compreender os dados.
  • Mapas e diagramas: quando a posição dos elementos é importante para entender a informação.
  • Jogos, vídeos e apresentações: quando sua organização visual em duas dimensões é necessária para o uso ou a compreensão.
  • Algumas interfaces de edição: quando é necessário manter ferramentas visíveis enquanto o conteúdo é manipulado.

Importante: a exceção não se aplica automaticamente à página inteira. Por exemplo, uma tabela pode precisar de rolagem lateral, mas os parágrafos e controles ao redor ainda devem se reorganizar.

No caso de uma tabela, cada célula também deve se reorganizar, salvo se seu próprio conteúdo precisar de duas dimensões para fazer sentido ou funcionar.

Sempre que possível, é melhor limitar a rolagem lateral à própria área que precisa dela, em vez de fazer toda a página rolar para os lados.

A existência de uma barra horizontal na página não é, por si só, uma falha. Verifique se o conteúdo que não possui exceção pode ser lido e utilizado sem depender dessa rolagem lateral.

Atenção: aplicar 400% em uma janela muito larga não garante, por si só, uma área útil de 320 pixels CSS. Por outro lado, uma área menor que 320 pixels CSS pode apresentar dificuldades que exigem análise adicional antes de classificá-las como falha do critério 1.4.10.

Este procedimento considera páginas normalmente lidas com rolagem vertical. Para conteúdo desenvolvido para rolagem horizontal, o critério de refluxo também apresenta uma referência de altura de 256 pixels CSS.

4. Registre o resultado

Anote cada problema separadamente. Uma captura de tela ajuda, mas descreva também os passos necessários para reproduzi-lo.

Descreva onde ocorreu, o que você fez e o que deixou de funcionar ou de aparecer.

Exemplo: “No zoom de 200%, o botão ‘Enviar’ ficou encoberto pelo aviso de cookies e não pôde ser acionado.”
